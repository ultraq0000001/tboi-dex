# TBOI PockeDEX

A Pokédex-style Android app for browsing The Binding of Isaac items and
trinkets — searchable list view, tap into a detail view with effect, quality
rating, pools, unlock info, and synergies.

@AGENTS.md

See `REQUIREMENTS.md` for the planned content-scope expansion (Bosses,
Characters, Monsters, etc.) and feature backlog (camera item lookup, version
filter, personal collection stash) beyond this baseline. See `TODO.md` for
concrete, scheduled tasks dictated one at a time as work is planned.

## Stack

- Expo SDK 57 (React Native 0.86, React 19) + TypeScript, `blank-typescript` template
- React Navigation (`@react-navigation/native` + `native-stack`) for list → detail navigation
- No backend — all item/trinket data is bundled locally as JSON (no network calls)
- Native pixel-perfect icon rendering via `expo-pixel-perfect` (see below)

## Commands

- `npm start` — launch Metro/Expo dev server (scan QR with Expo Go on Android)
- `npm run android` — `expo run:android` (needs a local Android toolchain + native build)
- `npm run ios` — `expo run:ios` (needs Xcode)
- `npm run web` — `expo start --web`
- `npx tsc --noEmit` — type-check
- `node scripts/generate-item-icons.mjs` — regenerate `generatedItemIcons.ts` when data/assets change
- `node scripts/generate-trinket-icons.mjs` — regenerate `generatedTrinketIcons.ts` when data/assets change
- `npx expo export --platform android` — verify the app bundles without a device (cleanup: delete `dist/` after)

## Structure

- `App.tsx` — navigation container + stack (`Home` → `ItemList` → `ItemDetail`, `Home` → `TrinketList` → `TrinketDetail`, or `Home` → `ComingSoon`)
- `src/screens/HomeScreen.tsx` — landing page; category hub grid (Items + Trinkets + 12 planned categories)
- `src/screens/ComingSoonScreen.tsx` — generic placeholder for categories without data/screens yet
- `src/data/categories.ts` — category list backing the hub (`key`, `label`, `iconKey`, `implemented`)
- `src/data/categoryIcons.ts` — `iconKey → require(...)` registry for hub button icons (`assets/media/Content/{category_name}-button.webp`)
- `src/components/CategoryTile.tsx` — hub grid tile, dims + placeholder initials when unimplemented or no icon registered
- `src/types/item.ts` — `Item` shape: id (slug), itemId (numeric id), name, type (`passive`/`active`/`trinket`/`familiar`), quality (0–4), quote, effect (`item_effect`), pools, unlock text, iconKey, tags, synergies
- `src/types/trinket.ts` — `Trinket` shape: id (slug), name, quote, effect, unlock, quality (0–4), pools, iconKey, addedIn, synergies
- `src/types/navigation.ts` — `RootStackParamList` for typed navigation
- `src/data/items_rebirth.json` — the bundled item dataset (~341 items; see below)
- `src/data/items.ts` — loads `items_rebirth.json`, normalizes each raw record into an `Item[]` (slug id, numeric itemId, type/quality clamping, synergy flattening), resolves `iconKey`
- `src/data/trinkets_rebirth.json` — the bundled trinket dataset (60 trinkets, all from Rebirth)
- `src/data/trinkets.ts` — loads `trinkets_rebirth.json`, normalizes each raw record into a `Trinket[]`, resolves `iconKey`
- `src/data/itemTypes.ts` — shared per-type labels (`TYPE_LABELS`) + colors (`TYPE_COLORS`) used by item tiles and the item detail screen
- `src/data/generatedItemIcons.ts` — AUTO-GENERATED by `scripts/generate-item-icons.mjs`: static `require()` registry of icons under `assets/media/Collectibles/` (keyed by id-based `collectible_<id>_icon.png`), plus `iconFilenameForItem(raw)`. Do NOT edit by hand — rerun the generator.
- `src/data/generatedTrinketIcons.ts` — AUTO-GENERATED by `scripts/generate-trinket-icons.mjs`: same pattern for `assets/media/Trinkets/` (`trinket_<id>_icon.png`) with `iconFilenameForTrinket(raw)`. Do NOT edit by hand.
- `src/data/itemIcons.ts` / `src/data/trinketIcons.ts` — thin re-exports of the generated registries
- `src/data/icons.ts` — merged registry (item + trinket icons) that `PixelIcon` resolves against; keys never collide (`collectible_*` vs `trinket_*`)
- `src/components/PixelIcon.tsx` — renders an item/trinket icon with nearest-neighbor scaling (see Pixel-perfect below)
- `src/screens/ItemListScreen.tsx` — searchable 3-column grid with type filter chips
- `src/screens/ItemDetailScreen.tsx` — full item detail view (#id + name, quote, colored type, quality stars, effect, unlock, synergies, found-in pools)
- `src/components/ItemTile.tsx` — grid tile (icon via `PixelIcon`, placeholder initials if no icon)
- `src/screens/TrinketListScreen.tsx` — searchable 3-column grid
- `src/screens/TrinketDetailScreen.tsx` — full trinket detail view (quote, effect, unlock, added-in, synergies)
- `src/components/TrinketTile.tsx` — trinket grid tile
- `src/components/QualityStars.tsx` — 0–4 star quality indicator

## Data set

`src/data/items.ts` loads the full **~341-item Rebirth set** from
`items_rebirth.json` at build time (imported statically via `resolveJsonModule`).
`src/data/trinkets.ts` similarly loads the **60-trinket Rebirth set** from
`trinkets_rebirth.json`.

Notes:
- Item `id` is a URL-style slug derived from the name; the numeric in-game
  collectible id is kept separately as `itemId` and shown as `#<itemId>` on the
  detail screen.
- Item `unlock` is hardcoded to `"Starts unlocked"` for all items (not yet mined
  from real data). Trinkets carry real unlock text from the source dataset.
- Treat `quality`/`quote`/`effect` values as best-effort approximations from the
  source JSON, not wiki-verified.

## Icon generation

Same id-based pattern for both content types:

- Item icons live under `assets/media/Collectibles/` as `collectible_<id>_icon.png`
  (~340 registered; ids come from `items_rebirth.json`).
- Trinket icons live under `assets/media/Trinkets/` as `trinket_<id>_icon.png`
  (59 registered of 60 — `trinket_57_icon.png` for "???'s Soul" is missing from
  the folder, so that trinket falls back to placeholder initials).

`scripts/generate-item-icons.mjs` and `scripts/generate-trinket-icons.mjs` scan
their folder plus the matching dataset JSON and regenerate the respective
`generated*Icons.ts`, so the registries can never drift from disk. After
adding/removing icon files or changing the data JSON, run:

```bash
node scripts/generate-item-icons.mjs
node scripts/generate-trinket-icons.mjs
```

`iconFilenameForItem(raw)` / `iconFilenameForTrinket(raw)` resolve an entry's icon
from its id-based `icon` field but only return it when the file is in the
registry; otherwise they return `null` and the entry falls back to placeholder
initials in the tiles/detail screens.

## Pixel-perfect rendering

`PixelIcon` (`src/components/PixelIcon.tsx`) renders item/trinket sprites with
nearest-neighbor scaling so the pixel art stays crisp. On iOS/Android it uses
the native `expo-pixel-perfect` module; on web it falls back to RN `<Image>`
with `imageRendering: 'pixelated'`.

Crucial: `expo-pixel-perfect` ships native code, so it **does not work in
Expo Go** (that environment throws `Cannot find native module 'ExpoPixelPerfect'`).
`PixelIcon` detects Expo Go via `Constants.executionEnvironment === 'storeClient'`
and degrades to a regular `<Image>` so the app stays usable there. True
pixel-perfect rendering requires a development/build binary.

## Android / build config

- `app.json`: package id `com.kukushioku.tboipockedex`, dark UI style, `newArchEnabled: true` (SDK 57 New Architecture, required by the module), `expo-asset` config plugin
- `eas.json`: **configured** with `development` (`developmentClient: true`), `preview`, and `production` profiles
- No local Android SDK/JDK on this machine — native builds go through **EAS (cloud)**: `npx eas-cli login && npx eas-cli init`, then `npx eas-cli build --profile development --platform android`. See `README.md` for the full workflow.
